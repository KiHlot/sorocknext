# Роли и общие правила

## Контекст проекта

- **Проект**: Новостной портал `sorock.ru`.
- **Задача**: Переписать фронтенд с React SPA на **Next.js (App Router, TypeScript)**.
- **Бэкенд**: пока **WordPress (REST API)**, в будущем миграция на **Laravel** (этап отложен).
- **Авторизация**: **будет полностью удалена позже**, пока реализована временно. Портал публичный.
- **Документация**: все паттерны описаны в `pattern-front.md` и `pattern-back.md`.

---

## Общие правила для ассистента

### Код и стиль

1. **Генерируй код строго по указанным правилам**:
    - **Только абсолютные импорты** (`@/...`).
    - Компоненты – стрелочные функции с явным типом (`FC<Props>` или `ReactElement`).
    - Все функции и методы должны иметь **явные типы аргументов и возврата**.
    - Используй современный синтаксис (стрелочные функции, шаблонные строки, деструктуризацию, `async/await`).

2. **Для стилей** используй **SCSS-модули** (если не указано иное). Глобальные стили допустимы только в `src/styles/`.

3. **Именование файлов** должно соответствовать правилам ESLint (`unicorn/filename-case`) и структуре проекта (см. `structure.txt`).

4. **Типизация**:
    - Все интерфейсы — с постфиксом `IF` (например, `UserIF`, `PageIF`).
    - Все типы — с постфиксом `T` (например, `StepT`, `ValueOfT`).

- **Для форм**:
    - Если форма **без `context`** — используй `ObjectSchema<InterfaceIF>` и передавай тип вручную.
    - Если форма **с `context`** — используй `InferType<typeof schema>` для автоматического вывода

---

### Структура и архитектура

5. **Обязательно учитывай содержимое** `structure.txt`, `pattern-front.md` и `pattern-back.md`:
    - Это определяет существующие файлы, избегает дублирования, соблюдает единый стиль и правильное размещение новых файлов.

6. **Серверные компоненты — по умолчанию**. Клиентские компоненты используй только там, где нужна интерактивность (формы, слайдеры, модалки), и помечай их директивой `'use client'`.

7. **Для одиночных записей** используй `generateStaticParams` + ISR (`revalidate`) для всех 5000+ статей.

---

### Данные и API

8. **Все данные для фронта получай через публичные эндпоинты WordPress REST API** (без JWT). Авторизация не используется (временно реализована).

9. **Переменные окружения**: все URL и чувствительные данные бери из `process.env` (например, `NEXT_PUBLIC_WP_API_URL`). Не хардкодь их в коде.

10. **Изображения**: используй `next/image` с `remotePatterns` для доменов WordPress (локальный и продакшн).

11. **Даты**: для форматирования и вычислений используй библиотеку `dayjs` (уже установлена).

---

### SEO и метаданные

12. **SEO**: используй `export const metadata` или `generateMetadata` в серверных компонентах. Используй хелпер `setSeo` из `@/helpers/setSeo`.

---

### Обработка ошибок

13. **Для ошибок API** используй `catchError` из `@/helpers/validation/error/error.helpers`.
14. **Для форм** используй `parseResponse` для обработки стандартизированных ответов API.
15. **На страницах** используй `not-found.tsx` для 404.

---

### Дополнительные правила

16. **Старайся выдавать один наиболее подходящий результат** (максимум два, если варианты принципиально отличаются).
17. **Не додумывай и не придумывай то, о чём не просят** – строго по заданию.
18. **Если требуется дополнительная информация** – я обращусь к этим файлам или запрошу уточнения.
19. **Учитывай пакеты, которые используются на проекте и указаны в файле `package.json`.**

## Skills

Скиллы проекта

| Скилл               | Описание                                                                              |
| ------------------- | ------------------------------------------------------------------------------------- |
| `@front`            | Задача касается только фронтенда (компоненты, страницы, стили)                        |
| `@back`             | Анализ или вопрос про бэкенд (для справки)                                            |
| `@api`              | Добавление или изменение эндпоинта в `src/api/`                                       |
| `@structure`        | Обновление `structure.txt` — перечитать его                                           |
| `@prompt`           | Обновлённые версии файлов правил (`rooles.md`, `pattern-front.md`, `pattern-back.md`) |
| `@fix + код ошибки` | Ошибка — предложить исправление                                                       |
| `@generate`         | Создать новый компонент/страницу/файл по описанию                                     |
| `@refactor`         | Переработать существующий код                                                         |
| `@check`            | Проверить код на соответствие правилам                                                |
